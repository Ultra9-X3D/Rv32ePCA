## 三个 RTL 模块

| 模块 | 职责 | 源码 |
| --- | --- | --- |
| `Rv32ePca` | 将 Frame 的 66 位用户接口转换为 APB 信号 | [顶层](../rtl/Rv32ePca.v) |
| `Apb4Rv32ePca` | 保存操作数，接收 START，提供结果、状态和 IRQ | [寄存器接口](../rtl/Apb4Rv32ePca.v) |
| `PcaDatapath` | 锁存命令，并行运算并提交 32 位结果 | [数据通路](../rtl/PcaDatapath.v) |

```text
Frame 用户引脚 → Rv32ePca → Apb4Rv32ePca → PcaDatapath
                                   ↑          │
                                   └─ 结果、完成状态
```

Frame 集成测试路径为：Verilog 测试平台 → FrameTop 用户引脚 → Rv32ePca → Apb4Rv32ePca → PcaDatapath。APB 是用户设计内部采用的寄存器访问协议，不表示存在 SoC。Frame 框架需另外提供，见[测试说明](../README.md)。

## 四路 INT8 是怎样计算的

每个 32 位操作数装四个字节：lane 0 位于 `[7:0]`，lane 1 位于 `[15:8]`，lane 2 位于 `[23:16]`，lane 3 位于 `[31:24]`。

例如 A = `[1,2,3,4]`、B = `[5,6,7,8]`（从 lane 0 开始列）：

```text
A = 0x04030201，B = 0x08070605
DOT4 = 1×5 + 2×6 + 3×7 + 4×8 = 70
ACC = 10 时，DOT4+ACC = 80
```

四个 signed 8×8 乘法器同时算乘积，再符号扩展、相加得到 32 位结果。这是一次四元素点积；长向量需要软件分组提交。ACC 是软件写入的初值，结果不会自动回写 ACC。

## 操作码

| 值 | 运算 | 结果格式 |
| --- | --- | --- |
| `0x0` | 四路字节加法 | 每路保留低 8 位，不饱和 |
| `0x1` | 四路字节减法 | 每路保留低 8 位，不饱和 |
| `0x2` | 四路无符号绝对差 | 四个打包字节 |
| `0x3` | A XOR B | 32 位 |
| `0x4` | 四路有符号点积 DOT4 | 32 位 |
| `0x5` | ACC + DOT4 | 32 位 |
| `0x6` | ACC + 四路无符号绝对差之和 | 32 位 |
| `0x7` | A AND B | 32 位 |
| `0x8` | A OR B | 32 位 |
| `0x9` | COPY A | 32 位 |
| `0xA`～`0xF` | 保留 | RTL 当前返回 0；调用方不应使用 |

DOT 的字节按补码 INT8 解释，绝对差按无符号字节解释。32 位累加溢出保留低 32 位，不做饱和。

## 执行时序

| 上升沿 | 动作 | 边沿后的状态 |
| --- | --- | --- |
| T0：接受 START | 锁存 opcode、A、B、ACC | BUSY=1，清旧 DONE/ERROR，PERF=0 |
| T1：提交结果 | 保存组合运算结果 | BUSY=0，DONE=1，PERF=1 |
| 后续 | 保持结果和 DONE | 写 IRQ_CLEAR 或启动新命令后清 DONE |

`PERF=1` 只统计内部计算周期，不包含 APB 写操作数、START、轮询和读结果的时间。

## 能力范围

现有设计没有 DMA、本地 SRAM、FIFO 或多级乘加流水线；输入来自寄存器，输出由软件读取。它可加速点积和短向量运算，但不是完整神经网络引擎。是否获得端到端加速，需要连同数据搬运和软件调用开销测量。
