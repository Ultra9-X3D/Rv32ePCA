# ws_0002 设计报告与功能验证审核记录

审核结论：报告的主要功能及面积、利用率数据有对应证据；本次原始 RTL 单元测试和带明确模型修正前提的零延时网表回归通过。当前证据支持所测试功能正确，尚不足以保证回片后功能、板级接口和全部工况均正常。提交前仍需闭合外部接口时序、最终 Frame 集成及组织方签核要求。

## 文档问题与修正

1. 原“复位后选择 Frame 编号”顺序不准确。验证用 FrameDesignControl 在复位期间采样编号、释放后停止采样，已改为先稳定编号并提供时钟，再释放复位和等待内部启动。最终编号与时序以组织方集成版本为准。
2. 补充双向数据线方向切换：Rv32ePca 的读输出使能为 PSEL && !PWRITE，SETUP 阶段已开始驱动，主机不能等到 ACCESS 阶段才释放数据线。
3. 补充同步复位需要有效时钟。PCA 寄存器接口含异步复位，计算数据通路使用同步复位，不能只给无时钟的复位脉冲。
4. 修正 BUSY 测试预期：计算仅一拍，正常 APB 访问至少包含两阶段，软件可能始终读不到 BUSY=1。忙时重复启动不能作为必然可通过合法板级事务触发的测试项。
5. 完成状态也会在接受新 START 或复位时清除，已补齐说明。

## 尚未闭合的验证

- 当前 SDC 仅创建 20 ns 时钟，没有 input/output delay；外部路径的时序裕量不能由内部 WNS 推导。需要真实 Frame 集成、外部驱动与负载条件，不能凭空补约束数值。
- 未完成 RTL 与提交网表的形式等价验证，以及带 SDF 的时序仿真。本次网表回归是 Verilator 功能模式，不能证明 X 态、电气争用、真实延时及所有输入序列均正确。
- 未验证最终封装引脚、供电、电平、最终 Frame 集成和硅上功能；亦未实现或验证 CPU 中断服务程序。
- 既有独立边界实验发现直接 APB 未对齐写会报 PSLVERR 但仍修改寄存器。当前 Frame 包装固定地址低两位为 0，该访问在本次提交接口不可达；今后若直接复用 APB 子模块，必须修复并回归。没有修改本次已生成的网表。

## 证据位置与复现

本仓库 `reports/verification/` 保存原始结果日志；`tests/` 保存 RTL 基线和网表测试平台。使用方法见仓库 README。PDK 和修正后的整库副本不随仓库分发；网表测试脚本只在本地 build 目录产生临时模型副本。

CPU 联合仿真日志为既有隔离实验结果，CPU、测试桥和整个 Frame 工程未包含在本仓库，因此独立克隆本仓库不能重现该项实验。

2026-09-18 审核没有修改设计 RTL、提交 DEF/网表或原始 PDK。本仓库的 RTL 与 ws_0002/origin 原始文件逐字节一致。
